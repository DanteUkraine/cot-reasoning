# Validator Regression Fixtures

Fixed flows the validator is run against after every change to
`scripts/validate-system-flow.sh` or to the output contract. Expectations live
in `expectations.tsv` (TSV: filename, expected exit code, required output
message or `-`). The runner also executes five built-in CLI cases.

Run the suite:

```bash
./scripts/run-test-flows.sh
```

## Markdown fixtures

| Fixture | Mode | Expected | What it protects |
|---------|------|----------|-------------------|
| `minimal-pass.md` | MINIMAL | exit 0 | MINIMAL untouched by the v5.2.0 disciplines: a flow with no new fields and the 12-line budget still passes |
| `basic-pass.md` | BASIC | exit 0 | BASIC contract with the Confidence Gate present passes |
| `standard-pass.md` | STANDARD | exit 0 | Full STANDARD contract: extended sections, Confidence Gate, Output Schema per step, loop fields declared as a set |
| `minimal-fail-step-budget.md` | MINIMAL | exit 1 | MINIMAL step budget (>3 steps rejected) |
| `minimal-fail-structural-budget.md` | MINIMAL | exit 1 | MINIMAL structural budget (>12 lines rejected) |
| `standard-fail-invalid-enums.md` | STANDARD | exit 1 | Invalid Reasoning Mode / Thinking Type / Complexity rejected |
| `standard-fail-invalid-pattern.md` | STANDARD | exit 1 | Invalid Pattern rejected |
| `standard-fail-tool-and-fields.md` | STANDARD | exit 1 | Invented tool name, missing step field, orphan loop fields, Tool without parameters |
| `standard-fail-no-gate.md` | STANDARD | exit 1 | A STANDARD flow without the Confidence Gate is rejected |
| `standard-fail-broken-loop.md` | STANDARD | exit 1 | Max Iterations declared without Exit Criteria / Escalation Policy is rejected |
| `basic-fail-generatedby-mismatch.md` | BASIC | exit 1 | Generated By version mismatch is rejected |
| `empty-fail-unreadable.md` | — | exit 1 | Empty / unreadable file is rejected |

## JSON fixtures

| Fixture | Expected | What it protects |
|---------|----------|-------------------|
| `json-pass-single-flow.json` | exit 0 | Single-flow (non-wrapper) JSON branch |
| `json-pass-orphan-warning.json` | exit 0 + warning | Orphan loop fields (exit_criteria / escalation_policy without max_iterations) warn but do not fail |
| `json-fail-invalid-syntax.json` | exit 1 | Broken JSON is rejected |
| `json-fail-broken-example.json` | exit 1 | Invalid enums, missing step fields, invented tool, empty findings/recommendations, wrapper version mismatch |
| `json-fail-missing-metrics.json` | exit 1 | Missing quality_metrics in BASIC |

## Built-in CLI cases

| Case | Expected | What it protects |
|------|----------|-------------------|
| no arguments | exit 2 | Usage error handling |
| nonexistent target | exit 2 | Target existence check |
| `-j` on a `.md` file | exit 2 | Mode/file-type mismatch (JSON) |
| `-m` on a `.json` file | exit 2 | Mode/file-type mismatch (markdown) |
| `-s` on a directory | exit 1 | "File not found" path |

## Coverage

The suite exercises 79 of the validator's 80 check templates (99%). The single
excluded path is the `jq`-missing check — it requires `jq` to be absent from
the environment; `jq` is documented as a prerequisite in the README.

## Adding a new check to the validator

Add a fixture that fails without the check and passes with it, register it in
`expectations.tsv`, then re-run the suite and the example suite:

```bash
./scripts/run-test-flows.sh
./scripts/validate-system-flow.sh -j assets/system-examples.json
```
